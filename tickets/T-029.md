# T-029 — Wire initialCityId prop and tab-level lazy query loading in VentureCapitalView

**Source finding:** AUDIT_REPORT.md §CPO-1 | Severity: P1 | Class: BROKEN / SUBOPTIMAL  
**Assigned tier:** INTERMEDIATE  
**Effort estimate:** 2h | **Sequence:** independent

## WHAT
In `src/client/views/VentureCapitalView.tsx`, the component declares `interface VentureCapitalViewProps { initialCityId?: string; }` but declares `export const VentureCapitalView: React.FC<VentureCapitalViewProps> = () => {` without destructuring or using `initialCityId`. Furthermore, on component mount, it fires six concurrent API calls in `Promise.all` (`fetchVCSummary`, `fetchVCFirms`, `fetchVCDeals`, `fetchVCSectors`, `fetchVCSignals`, `fetchVCSyndication`), downloading large datasets even when the user only views the Overview tab. This change:
1. Accepts `{ initialCityId }` in `VentureCapitalView` and displays a local context header when viewing a specific municipality.
2. Lazy-loads subtab datasets: on mount, only `fetchVCSummary()` and `fetchVCSectors()` are requested. `firms`, `deals`, `signals`, and `syndication` are fetched on-demand when the user switches to their respective subtabs.

## WHY
Improves component responsiveness, saves memory and network bandwidth, and connects cross-module navigation from `RegionalVCCard`.
