# T-055 — Enforce Expiry and Session Token Lifecycle in Auth Middleware

**Source finding:** AUDIT_REPORT.md §CTO-03 | Severity: P1 | Class: SUBOPTIMAL  
**Assigned tier:** SENIOR  
**Effort estimate:** 2h | **Sequence:** after T-054  

## WHAT
Refactor `src/server/auth.ts` to properly handle the token lifecycle:
1. When `/api/auth/verify?token=...` is called, verify the token is unused and unexpired, mark it `used = TRUE`, and issue a dedicated session token with a 30-day expiry returned in the response `{ success: true, user, sessionToken }`.
2. Update the `requireAuth` middleware to validate that the provided Bearer token exists, is associated with the user, and has `expires_at > NOW()`. If expired, return HTTP 401 `{ success: false, error: 'Session expired' }`.
3. Update `src/client/App.tsx` to store the returned `sessionToken` rather than the single-use magic link token.

## WHY
Currently, one-time magic link tokens are reused as infinite bearer tokens without verifying expiration timestamps in the `requireAuth` middleware, leaving user accounts exposed indefinitely without session invalidation or rotation.

## SCOPE — FILES
IN:
- `src/server/auth.ts`
- `src/client/App.tsx`
- `tests/auth.test.ts`

OUT:
- `src/server/routes.ts` (consumes `requireAuth`; do not modify route definitions)
- `src/db/schema.sql` (`auth_tokens` table already has `expires_at`, `used`, `user_id`, and `token`)

## ACCEPTANCE CRITERIA (testable, binary)
- [ ] AC1: `/api/auth/verify` issues a distinct session token with 30-day validity upon successful verification of a valid magic link token.
- [ ] AC2: `requireAuth` middleware checks `expires_at > NOW()`.
- [ ] AC3: `requireAuth` rejects expired tokens with HTTP 401.
- [ ] AC4: `App.tsx` stores `json.sessionToken` in `localStorage.getItem('auth_token')`.
- [ ] AC5: Tests in `tests/auth.test.ts` verify: (a) magic link generation, (b) token verification and session token issuance, (c) rejection of used magic links, (d) rejection of expired session tokens in `requireAuth`.

## TEST PLAN

Expected output: All authentication tests pass, confirming session expiration enforcement.

## CONSTRAINTS
- Use `crypto.randomBytes(32).toString('hex')` for secure tokens.
- No new external auth dependencies (keep lightweight with PostgreSQL `auth_tokens`).
