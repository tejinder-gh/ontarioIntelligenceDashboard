# T-057 — Add Retry Bounds and Failure Handling to Alert Worker

**Source finding:** AUDIT_REPORT.md §CTO-05 | Severity: P1 | Class: BROKEN  
**Assigned tier:** SENIOR  
**Effort estimate:** 2h | **Sequence:** independent  

## WHAT
In `src/server/cron.ts` and `src/alerts/watch-evaluator.ts`, add retry counting and failure state handling for alert notifications. Update the `audit_events` or notification delivery tracking to record failed attempts. If a notification fails delivery more than 3 consecutive times, mark it with `FAILED` or increment `retry_count`, preventing it from blocking subsequent notifications and avoiding an infinite retry loop on broken recipient addresses.

## WHY
Presently, if an email delivery fails (bounced address, invalid MX, network error), the notification is never marked sent and has no retry tracking. The worker retries the exact same failing email every 60 seconds indefinitely, spamming error logs and risking API throttling.
