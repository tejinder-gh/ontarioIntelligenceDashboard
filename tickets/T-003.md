# T-003 — Establish explicit geography taxonomy and longitudinal observation schema

**Source finding:** User Amendment #1, #11 | Severity: P0 | Class: BROKEN  
**Assigned tier:** SENIOR  
**Effort estimate:** 4h | **Sequence:** independent

## WHAT
Update the database schema and types to maintain an explicit geography model distinguishing: Province (`PROVINCE`), Census Division (`CD`), Census Subdivision (`CSD`), Upper-Tier Municipality (`UPPER_TIER`), Lower-Tier Municipality (`LOWER_TIER`), Single-Tier Municipality (`SINGLE_TIER`), and CMA/CA (`CMA`, `CA`). Update the observations schema to enforce an immutable temporal model (composite key includes `reference_year`, `vintage_date`, and revision tracking) so that historical releases of population, incomes, business counts, rents, and municipal budgets are never overwritten.

## WHY
Equating Ontario's 444 municipal governments with 444 CSDs is geographically inaccurate (e.g. Halton Region is an upper-tier municipality encompassing lower-tier CSDs Burlington, Oakville, Milton, and Halton Hills). Furthermore, overwriting old data destroys the platform's core historical moat.

IN:

OUT:

## ACCEPTANCE CRITERIA (testable, binary)
- [x] AC1: `geographies` schema includes explicit `municipal_tier` column with allowed values: `'SINGLE_TIER'`, `'UPPER_TIER'`, `'LOWER_TIER'`, `'UNORGANIZED'`, or `NULL` (for non-municipal census units like CDs/CMAs).
- [x] AC2: `geographies` schema maintains foreign key / relationship fields for `census_division_id` and `cma_id`.
- [x] AC3: `observations` table schema enforces composite uniqueness across `(geography_id, metric_id, reference_year, is_benchmark, benchmark_label)` with a `vintage_date` or `effective_date` timestamp ensuring temporal snapshots can coexist without overwriting.
- [x] AC4: A dedicated `observation_history` or temporal snapshot index is defined to track metric revisions over time.
- [x] AC5: TypeScript types in `src/ingestion/types.ts` and `src/client/types/index.ts` reflect the updated geography and observation models.

## TEST PLAN
1. Run schema verification script against PostgreSQL or in-memory runner to confirm tables, constraints, and indexes apply cleanly.
2. Verify that two observations with the same `geography_id` and `metric_id` but different `reference_year` (e.g. 2016 and 2021) coexist without collision or overwriting.
