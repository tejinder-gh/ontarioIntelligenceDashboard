# T-054 — Align Magic Link and Dossier Email URLs with Active Application Origin

**Source finding:** AUDIT_REPORT.md §CTO-02, §CPO-02 | Severity: P0 | Class: BROKEN  
**Assigned tier:** SENIOR  
**Effort estimate:** 2h | **Sequence:** independent  

## WHAT
In `src/alerts/email-dispatcher.ts`, replace the hardcoded fictitious URLs (`https://ontario-intelligence.example.com` and `http://localhost:5173/api/auth/verify?token=...`) with dynamic, configurable application URLs sourced from `process.env.APP_BASE_URL` (defaulting to `http://localhost:3000`). Ensure magic link URLs route the user to the web application root `/?token=${token}` (which the React client in `App.tsx` already listens for and verifies), rather than an unformatted raw JSON API endpoint. Update dossier access links to point to the web application with query params `/?city=${cityId}&category=${categoryId}&view=dossier`. In non-production environments without a valid Resend key, log the email body to console and return success rather than failing with 401.

## WHY
Emails sent to real users contain broken links pointing to dummy domains or incorrect ports (5173 instead of 3000), locking users out of both their authentication flow and their purchased dossiers.
