# T-034 — Implement rate limiting middleware and security headers in src/server/app.ts

**Source finding:** AUDIT_REPORT.md §CTO-15 | Severity: P1 | Class: BROKEN / SECURITY  
**Assigned tier:** SENIOR  
**Effort estimate:** 2h | **Sequence:** 2

## WHAT
In `src/server/app.ts`:
1. Implement in-memory IP rate limiting for sensitive state-modifying endpoints (`POST /api/checkout/dossier`, `POST /api/alerts/events`, `POST /api/launch/workspaces`).
2. Add security headers (`X-Content-Type-Options: nosniff`, `X-Frame-Options: SAMEORIGIN`, removal of `X-Powered-By`).

## WHY
Protects the API against denial-of-service, automated checkout spam, and database connection pool exhaustion.

## SCOPE — FILES
IN:
- `src/server/app.ts`
- `tests/health.test.ts`

OUT:
- `src/server/routes.ts`

## ACCEPTANCE CRITERIA
- [ ] AC1: Express server does not emit `X-Powered-By` header.
- [ ] AC2: Security headers (`X-Content-Type-Options`, `X-Frame-Options`) are set on responses.
- [ ] AC3: Sensitive POST endpoints throttle excessive requests (e.g. > 30 requests/minute per IP) with HTTP 429 Too Many Requests.
- [ ] AC4: Full test suite (`npm test`) passes with 0 failures.
