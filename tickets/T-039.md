# T-039 — Lock down alert operations

**Source finding:** AUDIT_REPORT.md §CTO-02 | Severity: P0 | Class: BROKEN
**Assigned tier:** SENIOR
**Effort estimate:** 4h | **Sequence:** independent

## WHAT

Make alert queue inspection, evaluation, and delivery unavailable to unauthenticated public callers. Keep only a narrowly validated public watch-registration endpoint; return no subscriber records or queue data through public APIs.

## WHY

The current endpoints disclose subscriber emails and let arbitrary callers alter notification delivery. This is a public-release blocker.

## SCOPE — FILES

IN: `src/server/routes.ts`, `src/server/app.ts`, `tests/alerts-diff.test.ts`
OUT: `src/alerts/watch-evaluator.ts` (do not alter matching logic), `src/db/schema.sql` (no migration), all payment/launch files.

## ACCEPTANCE CRITERIA (testable, binary)

- [ ] AC1: Unauthenticated alert reads, evaluation and delivery return no subscriber/notification data and cause no mutation.
- [ ] AC2: Public registration accepts only validated email, server-supported watch type and bounded values; invalid input is 400.
- [ ] AC3: Public alert writes are rate-limited.
- [ ] AC4: Tests prove public callers cannot retrieve or mutate another subscriber's records.
- [ ] AC5: `bun run test`, `bunx tsc --noEmit`, and `bun run build` pass.

## TEST PLAN

Add direct HTTP assertions, then run `bun run test`, `bunx tsc --noEmit`, and `bun run build`.

## CONSTRAINTS

- Follow Express/Zod patterns in `src/server/launch-routes.ts`.
- No new dependencies, identity system, email sender or admin-token system.
- An unavailable operator capability is safer than invented authorization.

## ROLLBACK

Revert the ticket commit. Do not restore public queue endpoints in production.

## BLOCKED PROTOCOL

If a production operator depends on an endpoint, STOP and report the required identity model.
