# T-053 — Connect User Vault View Button to Feasibility Dossier Viewer

**Source finding:** AUDIT_REPORT.md §CPO-01, §DES-02 | Severity: P0 | Class: BROKEN  
**Assigned tier:** INTERMEDIATE  
**Effort estimate:** 2h | **Sequence:** independent  

## WHAT
In `src/client/components/UserPortalModal.tsx`, remove the placeholder `alert("In a production environment, this would open the secured PDF...")` and wire the "View Secured Report" button to directly launch the `FeasibilityDossierModal` populated with the purchased report's `city_id` and `category_id`. Fix the badge display by using `dossier.id` or `dossier.city_id` instead of the non-existent `dossier.report_id`.

## WHY
Customers who purchase dossiers and open their account vault cannot access their purchased reports. Clicking the view button triggers a developer mock alert, degrading trust and leaving the customer stranded without their paid intelligence.

## SCOPE — FILES
IN:
- `src/client/components/UserPortalModal.tsx`
- `src/client/App.tsx`

OUT:
- `src/server/routes.ts` (`/api/user/dossiers` already returns the correct order array)
- `src/client/components/FeasibilityDossierModal.tsx` (modal is already capable of displaying any city/category)

## ACCEPTANCE CRITERIA (testable, binary)
- [ ] AC1: `UserPortalModalProps` accepts an `onViewDossier: (cityId: string, categoryId: string) => void` callback prop.
- [ ] AC2: Clicking "View Secured Report" invokes `onViewDossier(dossier.city_id, dossier.category_id)` and closes the user portal modal.
- [ ] AC3: `App.tsx` handles `onViewDossier` by setting the active city/category and opening `FeasibilityDossierModal`.
- [ ] AC4: The report badge replaces the undefined `{dossier.report_id}` with a formatted order ID badge (e.g. `ORDER #${dossier.id}`).
- [ ] AC5: Build succeeds cleanly with `bun run build`.
