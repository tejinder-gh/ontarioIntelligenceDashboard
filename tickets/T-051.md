# T-051 — Add strict Zod validation to /api/checkout/dossier

**Source finding:** AUDIT_REPORT.md §Phase 1 | Severity: P1 | Class: SUBOPTIMAL
**Assigned tier:** INTERMEDIATE
**Effort estimate:** 1h | **Sequence:** independent

## WHAT
Update `/api/checkout/dossier` in `src/server/routes.ts` to strictly validate `cityId` and `categoryId` using `zod` before generating a Stripe session. 

## WHY
Currently, the route only checks truthiness, allowing arbitrary string injection into the Stripe session metadata. This can lead to malformed orders being created.

## SCOPE — FILES
IN: 
- `src/server/routes.ts`
- `tests/dossier.test.ts` (to add validation tests)

OUT: 
- `src/db/*`

## ACCEPTANCE CRITERIA (testable, binary)
- [ ] AC1: `z.object({ cityId: z.string().startsWith('CSD_'), categoryId: z.string() })` schema is used to parse the request body.
- [ ] AC2: A 400 Bad Request is returned if the validation fails.
- [ ] AC3: The route additionally checks if the city exists in the `geographies` table and category in `taxonomies` table before proceeding.
- [ ] AC4: A test in `tests/dossier.test.ts` verifies that passing an invalid `cityId` returns 400.

Expected output: The new 400 Bad Request test passes.
