# T-010 — Dedicated "Not Enough Data" State & Insight Request Persistence Engine

**Source finding:** User Spec §1, §41 | Severity: P0 | Class: USER_EXPERIENCE & DATA_ENGINEERING  
**Assigned tier:** SENIOR  
**Effort estimate:** 4h | **Sequence:** P0

## WHAT
Implement the dedicated "Not Enough Data" UI component and insight request backend engine. When an analytical metric is missing or unobserved at the requested resolution (e.g. asking for municipal spending breakdown or neighbourhood-level commercial rent on an unseeded municipality), render a structured diagnostics state explaining:
1. Requested metric name and description
2. Requested geography
3. Nearest available geography resolution (e.g. CMA, Census Division, or Ontario benchmark)
4. Latest available period
5. Authoritative sources checked
6. Clear diagnosis: whether missing ingestion or genuinely unavailable upstream
7. Whether a broader benchmark exists
8. "Request this insight" interactive trigger that persists the user request into `requested_insights`.

Provide an administrative/internal endpoint `GET /api/insights/requests` showing priority rankings of missing datasets ordered by request volume.

## WHY
Never silently substitute or fabricate values. Giving users transparency into data boundaries while capturing unmet demand builds customer trust and focuses engineering ingestion priorities directly on high-demand datasets.

## SCOPE — FILES
IN:
- `src/db/schema.sql` (Create `requested_insights` table)
- `src/client/components/NotEnoughData.tsx` (Specular glass diagnostic component)
- `src/server/routes.ts` (`POST /api/insights/request`, `GET /api/insights/requests`)
- `tests/missing-data.test.ts` (Unit and integration tests)

## ACCEPTANCE CRITERIA
- [ ] AC1: `requested_insights` table records geography, metric, category, user context, and timestamp.
- [ ] AC2: `POST /api/insights/request` accepts requests and persists them into the database.
- [ ] AC3: `GET /api/insights/requests` returns aggregate counts and priorities by metric/geography.
- [ ] AC4: `NotEnoughData.tsx` renders all 7 diagnostic points plus the interactive request button.
- [ ] AC5: Tests verify proper handling when querying an unpopulated geography or missing metric.
