# T-046 — Implement Stripe Checkout Backend & Webhook

**Source finding:** AUDIT_REPORT.md §3 | Severity: P0 | Class: MISSING
**Assigned tier:** SENIOR
**Effort estimate:** 4h | **Sequence:** after T-045

## WHAT
Integrate the `stripe` Node SDK to create a Checkout Session for the $199 Location Feasibility Dossier and handle the `checkout.session.completed` webhook to fulfill the order.

## WHY
Currently, the `/api/checkout/dossier` endpoint returns 503 to prevent fake purchases. Monetization is the core missing piece of the application's business model.

## SCOPE — FILES
IN:  `src/server/routes.ts`, `src/server/app.ts`, `package.json`, `src/db/schema.sql`
OUT: `src/client/*` (Frontend UI will be handled in a separate ticket)

## ACCEPTANCE CRITERIA (testable, binary)
- [ ] AC1: `POST /api/checkout/dossier` returns a valid Stripe Checkout URL.
- [ ] AC2: `POST /api/webhooks/stripe` handles the `checkout.session.completed` event and updates a new `dossier_orders` table.
- [ ] AC3: Unlogged or unsigned webhooks return 400.
- [ ] AC4: Stripe SDK is added to `package.json`.

## TEST PLAN
Write a test that mocks `stripe.checkout.sessions.create` and verifies the JSON output contains `url`. Write a test for the webhook signature verification.

## CONSTRAINTS
- Follow existing Express route patterns in `src/server/routes.ts`.
- Use the `postgres` driver for the database operations.
- Avoid any mock logic for the actual Stripe API (use the real SDK).

## ROLLBACK
Revert commit on `routes.ts` and drop `dossier_orders` table.

## BLOCKED PROTOCOL
If Stripe API keys are not available in the environment, STOP and report.
